# AFE 结果收集

运行基准为 Harbor 0.25.0、Linux、独立评分环境。主任务是文件交接示例；可选 validation_task 还需要支持 Docker Compose 的后端。模板使用合成材料，不是已经完成科学验收的题目。

## 平台接入步骤

1. 用原生 Harbor 启动任务，保留 verifier 日志。test.sh 在评分容器的 `/logs/verifier/` 写 AFE 结果和有最终成绩时的 reward。
2. 一次 trial 结束后，无论 Harbor 将其记录为成功还是错误，都检查已下载的 verifier 日志目录；不要只处理成功 trial。
3. 在平台侧执行（路径替换为该次 trial 的实际目录）：

```sh
python3 平台接入/afe_contract.py collect /path/to/trial/verifier --supports-over-target true --output /path/to/collected_result.json
```

参数 true/false 从该题 metadata.afe.supports_over_target 取得。需要补充平台已有运行错误时可加 `--runtime-error "简短诊断"`，仅用于 AFE 文件缺失时的归因线索。

输出 disposition=scored 时有最终 score/reward；pending_review、evaluation_error、unmapped_status 都没有最终 reward，分别转复核、故障处理或状态接入。未知状态的原始结果会保留。收集器不会自动重试任务或决定榜单分母。

collect 退出码 0 表示已取得一致的最终成绩，3 表示已识别的未决/错误/未接入状态，2 表示工具参数或文件操作错误。完整信息以输出 JSON 为准。

## 题目作者侧

tests/afe_contract.py 提供 write_result：校验结果，写 afe_result.json，并按目标是否达成写 reward.json；非最终状态清除此前 reward，不制造 0 分。作者也可以自行实现同一接口。

Harbor 原生结果模型只接受数值 reward。pending_review 等不会变成 Harbor 原生新状态，可能被记录为缺 reward；平台需要运行上述收集步骤才能恢复 AFE 语义。本目录是可调用适配器，不是已经注册到某个现网服务的插件。

## validation 示例

environment/docker-compose.yaml 启动 main 和 validation；主容器只复制 tools，服务私有内容仅进入服务镜像。查询预算为 3，重复候选复用结果、无效请求不扣费；state.py 用服务侧锁记录查询。collect 在 Agent 阶段结束后执行 export_state.py，封存状态，再从 service=validation 收集快照。tests 读取快照和最终 query_id。

主容器配置 public 网络以允许客户端访问服务，服务不发布宿主端口；实际运行平台按自己的网络能力接入。服务资源单独为 1 CPU/256 MB。每次尝试使用新的容器状态，不复用前一次的状态目录。

只有必须衔接额外外部平台生命周期时才需要 harness/。平台负责调用和实际放置路径，Agent 只使用已提供的工具。

## 验证范围

本次提供结构检查、合成接口/状态用例和服务状态函数检查。没有在控制板运行 Harbor、Docker、远程服务或科学任务。正式运行方还需验证容器构建、客户端连通、侧服务 collect 和日志归档链路。
